# v0.15.0 - 2026-11-25

> 🧠 **会话驱动重构（对齐 qq-bridge）**：普通消息不再各自触发一轮跑图，改成「未读队列 + 状态机 + 单调度器」三层。消息只入队，由每秒 tick 的调度器在静默窗口、在途标记、发言冷却、提交限流四道闸都通过后才提交一窗；跟随窗口整块删除。

## Added

- `core/buffers/message_queue.py`：`MessageBufferStore` / `ThreadQueue` / `MessageEntry` —— 每会话一条未读队列，带序号、时间戳、已读水位；满了只丢最旧的「没叫我」的消息。
- `core/social/state.py`：`ChatState`（diving / active）、`SessionSocial`、`SocialStore` —— 状态机、pending 唤醒、提交与发言时间戳、在途标记、每分钟/每小时滑窗限流、发言冷却、active 时长随机区间与冷场回退、在途超时。
- `core/social/policy.py`：`WakeReason` / `classify` —— 被 @ / 被叫昵称 / 关键词族 / 提问句 / 引用 / 随机 / 聊天状态跟一句，纯标准库、可单测。
- `core/social/scheduler.py`：`Scheduler` —— 单 asyncio 任务每秒 tick：状态超时 → 静默检查 → 提交频率 → `decide` → 提交一窗。
- `core/delivery/throttle.py`：`SendGate`（每会话每分钟/每小时发送上限）、`burst_gap`（分条停顿，含长停顿概率）。
- `core/delivery/snapshot.py`：快照头（唤醒理由 / 未读条数 / 已读水位）、`[HH:MM:SS · 多久前]` 时间前缀、旧消息警告、按字数预算裁剪并注明省略条数。
- 配置三块：`social.*`（状态机与限流）、`snapshot.*`（未读快照）、`delivery.*`（发送节流）；`config.example.yaml` 与 README 配置示例同步重写。
- `docs/social-state-machine.md`：设计稿 + 落地差异章节。
- 测试 51 个：`test_message_queue` / `test_social_policy` / `test_social_state` / `test_scheduler` / `test_delivery` / `test_replay`（合成时钟回放，断言提交序列）。

## Changed

- `QQChannelMessage` 改成未读快照：`(entries, omitted, reason, delivered_seq)`；`to_content()` 带唤醒理由、未读数、已读水位、每条时间前缀与「你看到的不是全部」提醒。
- `QQChannel.reply()`：发送前按 `SendGate` 与 `burst_gap` 节流；发送结束统一收尾（推进已读水位、记发言时间、清在途标记）。
- `main.py`：`on_load` 建三层容器并启动调度器；`on_message` 只做授权、写语料、记录与状态判定。
- 共享容器键：`core.thread_backlog` → `core.message_buffer`，新增 `core.social_store`。

## Removed

- 跟随窗口整套逻辑：`followup_minutes` / `followup_messages` / `recent_chat_limit`，`ThreadBacklog`、`watch_thread` / `watch_until_quiet` / `submit_window` / `self.tasks`、`addressed_windows`。
- `submit.quiet` / `submit.chance` / `submit.cooldown`：迁到 `social.*`；旧字段被 pydantic 忽略。

## Fixed

- **一条消息触发一次跑图**：普通消息只入队，提交必须同时过静默、不在途、发言冷却、提交频率四道闸，一次被叫最多按限流跟几句。
- 跟随窗口自激（0.14.1 的补丁）被结构性删除，不再需要「续窗/不续窗」的补丁。

## Breaking

- 配置字段迁移：`submit.quiet/chance/cooldown/followup_*/recent_chat_limit` 删除或改名，旧配置需要按 `config.example.yaml` 重新映射。
- `QQChannelMessage` 构造函数签名变化；共享容器键变化。
- `social.enabled: false` 时退回「被叫即提交」的旧行为（不会攒批、不限流），仅建议排障时临时使用。

## Notes

- 私聊只豁免提交限流与发言冷却，仍受发送频率上限约束。
- 状态全部在进程内，重启后回到潜水、水位清零；已读上下文靠主包 checkpoint。
- poke（戳一戳）唤醒仍未接入：ncatbot 的 poke 是 notice 事件，当前只挂了 `on_message`。
- 冷场试探 / 主动开话题未实现（设计稿 P4）。
