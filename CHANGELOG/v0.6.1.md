# v0.6.1 - 2026-11-12

> 🔤 **`qq_platform_tools` 新增 `transcribe_qq_voice`**。以前收到语音只能看到一行 `[语音 文件名 大小](URL)`，模型拿不到说的什么。现在可以按消息 id 调 QQ 自带的转文字，把一条语音变成正文。不用另配 STT 供应商、不用装 litellm、不产生额外费用。

## Added

- `plugins/qq_platform_tools/tools/transcribe_qq_voice.py`：工具 `transcribe_qq_voice(message_id)`，底层是 `api.qq.query.fetch_ptt_text`（NapCat 的 `fetch_ptt_text` → QQ 的 `translatePtt2Text`），返回转写文本。
  - 有文本直接返回文本，不是 JSON —— 转写结果是给模型读的自然语言，包一层 JSON 只是多一对引号。
  - 空文本返回 `[转文字失败: 这条语音没有转出文字]`：QQ 自己没转出结果时不能返回空串，否则模型会当成「说了空白」。
  - 异常返回 `[转文字失败: <类型>: <消息>]`，与同目录其它工具一致。

## Note

- 这是 QQ 自带的转文字能力，**不是** litellm ASR：只需要 `api.qq`，不需要 `api.ai`，也不需要 `asr_model`。
- 受 QQ 侧限制：消息必须是语音、必须没被撤回、QQ 必须转得出来。三条任一不满足都会失败，失败原因由 NapCat 原样抛回。
- 依赖 `message_id` 定位，正好是渲染格式里元信息行的 `#<message_id>`。
- 新工具需要在 `miaoli_bot` 的 `plugins/tool_permission_manager/config.yaml` 里补条目，否则会被 `pick_tools` 摘掉。
