# v0.9.0 - 2026-11-15

> 🔊 **语音合成换成 MiMo**。原来走 `edge-tts`（mp3、`rate` / `pitch` 两个数值口子），现在走 MiMo 的 `/v1/chat/completions`（wav、一条自由文本的 `style` 语气指令），音色用预置 ID。顺带把语音前的尾巴符号过滤补上。配置字段全换，旧 `config.yaml` 需要跟着改。

## Added

- `core/tts/strip_tail_symbols.py`：`strip_tail_symbols(text)`。`w` 只在当尾巴用时删（前后不贴 ASCII 字母数字、后面接标点或收尾），`wifi` / `www.example.com` / `p≧w≦q` 不会被误伤；`♡♥❤💕💗` 全文删。
- `models/config/voice_config.py`：新增 `mimo_url`（接口地址）、`mimo_key`（API Key）、`model`（合成模型）、`style`（语气指令，放 `user` 角色，留空则只传朗读文本）。
- `config.example.yaml`、`config.yaml`：`voice` 段补上述四个字段。`mimo_key` 不在仓库里填值 —— `config.yaml` 被 `.gitignore` 忽略，Key 只写在那。

## Changed

- `core/tts/synthesize.py`：签名从 `synthesize(text, voice, pitch, rate)` 改成 `synthesize(text, url, key, model, voice, style)`。实现改成非流式一次 `POST`，目标文本放 `messages` 的 `assistant` 角色、`style` 放 `user` 角色，读 `choices[0].message.audio.data` 解 base64 拿 wav 字节，全程内存不落盘。HTTP 非 200、解析异常、空音频都留一条 warning 并返回 `None`。
- `core/channel/qq_channel.py` 的 `reply()`：合成送的是 `strip_tail_symbols(whole)` 而不是原文，长度门槛也在过滤后计数；命中语音仍是一条 `record` 段、`base64://` 直发，失败回退按段文字的逻辑不变。
- `core/tts/__init__.py`、`core/__init__.py`：多转出 `strip_tail_symbols`。
- `README.md`：依赖从 `edge-tts` 改成 `httpx`，配置示例、目录树、语音章节、已知短板同步。

## Removed

- `pitch` / `rate` 两个配置字段。它们是 edge-tts 的数值口子（`+16Hz` / `+0%`），MiMo 没有对应参数，语气改由 `style` 一段自然语言描述。
- `edge-tts` 依赖。

## Note

- **音色只能靠预置 ID。** `mimo-v2.5-tts-voicedesign`（文本描述生成音色）与 `mimo-v2.5-tts-voiceclone`（音频样本复刻）都试过：同一个描述、同一段样本各跑多次，出来的人耳可辨不同，固定不住音色。所以 `voice` 只填预置音色名（`冰糖` / `茉莉` / `苏打` / `白桦` / `Mia` / `Chloe` / `Milo` / `Dean`）。
- **`style` 改不动音色**，只影响语速、音高走势、停顿与情绪。音色、年龄感、音质由 `voice` 决定。
- **合成延迟 7~15 秒。** 非流式要等整段推理完，10~30 字的一条通常 7~15 秒，偶发上百秒。命中语音的那条回复会明显晚于正常打字节奏发出。
- **`base64://<wav>` 还没在 NapCat 真机验证过。** 收不下会在日志里留一条 `语音发送失败 回退到文字`。
- **文字路径不做任何过滤。** 没命中语音时 `♡` / `w` 原样发出去。
