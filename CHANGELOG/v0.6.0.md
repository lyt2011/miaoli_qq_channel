# v0.6.0 - 2026-11-11

> 🧱 **`to_content()` 从 ob11 JSON 改成 markdown 文本**。原来一次开窗的全部事件被 `json.dumps` 成一份 JSON 数组交给主包：每个事件都带着 `post_type` / `message_type` / `sub_type` / `message_seq` / `real_seq` / `message_format` / `target_id` / `font` 等十几个固定键，一条十来个字的「喵」要占 600 字符。实测 JSON 骨架占整份负载的 **93%**，真正的正文只占 0.7%。现在渲染成「元信息行 + 每段一行」，私聊压 5.6 倍、群聊压 6.8 倍，模型也不用再从字段里抠内容。

## Changed

- `QQChannelMessage.to_content()` 不再 `json.dumps`，改为把每个事件渲染成 `render_event(event)` 并用换行拼接；没有事件时仍给空串。
- 元信息行格式 `# [<元信息>] <发送者显示名>(<QQ号>):`：
  - 群消息：`群<群号> <群名> <YYYY-MM-DD HH:MM> #<message_id>`
  - 私聊：`<YYYY-MM-DD HH:MM> #<message_id>`（会话号不再重复，`(QQ号)` 里已有）
  - 时间取自事件 `time`，按本机时区格式化，不再以 unix 数字出现
  - `message_id` 放进元信息，供 `query_message` / `delete_message` 定位
- 消息段一行一段：`[文本] …` / `[表情 <id>]` / `[@ <qq>]` / `[回复 <id>]` / `[图片 文件名 大小](URL)` / `[语音 …]` / `[视频 …]` / `[文件 …]` / `[转发 <id> <n>条]`；未注册的段兜底成 `[<类型> <预览>]`。
- 正文内部换行替换成 `⏎`，保证「一段一行」不被打破。

## Added

- `core/channel/render_event.py`：`render_event(event)` 渲染单个事件。
- `core/channel/render_segment.py`：`render_segment(segment)` 渲染单个消息段。
- 两个函数从 `core.channel` / `core` 转出。

## Note

- **破坏性**：拿到 `to_content()` 的调用方现在得到的是纯文本，不再是可 `json.loads` 的数组。通道内部仍保留 `self.events` 原始事件，需要结构化数据从那里取。
- `forward` 段的转发生成内容**不内联**（内联一条转发能撑到 4,000+ 字符），只留 `[转发 <id> <n>条]`，要细节让模型调 `query_message`。
- `WakeMessage.to_content()` 不受影响，仍是原样字符串。
- 图片仍是 NapCat 的 URL 形式（不下载、不转 base64），单个 URL 数百字符，是渲染后最占体积的一项。
