# v0.1.0 - 2026-11-06

> 🧱 **首次发版：把 QQ 事件缓冲成消息通道**。本插件与 `miaoli_bot` 平级，依赖方向单向（`miaoli_qq_channel → miaoli_bot`）；`miaoli_bot` 只认识 `BaseChannel` / `ChannelMessage` 这套抽象，QQ 的收发细节全在这里。

## Added

- `main.py`：`MiaoLiQQChannel(NcatBotPlugin)`，`on_load` 用 `PluginConfig.model_validate()` 读配置、把 `PluginConfig` 与 `EventBuffer` 写进共享容器、调 `register_channel(QQChannel())` 注册通道，三件事的返回值都是注销函数，存进 `undo_list` 供 `on_close` 回放
- `main.py`：`record_anything` 挂 `@registrar.on_message()`，私聊与群聊事件一律 `record()` 进缓冲
- `consts.py`：共享容器键 `PLUGIN_CONFIG`（`miaoli_qq_channel/models.plugin_config`）与 `EVENT_BUFFER`（`miaoli_qq_channel/core.event_buffer`），前缀走本包命名空间，不写进 `miaoli_bot/`
- `core/event_buffer.py`：`EventBuffer(size)`，内部 `deque(maxlen=size)`；`record()` 用 `appendleft` 让最新的排在最前，`pop(count)` 按索引区间切成「移出」与「保留」两拨再重写 deque，`__len__` 供通道取长度
- `core/channel/qq_channel.py`：`QQChannel(BaseChannel)`，`name` 返回 `"qq"`，`drain()` 从 `EVENT_BUFFER` 取长度、`pop(全部)` 后 `[::-1]` 反转成「旧 → 新」，再包成 `QQChannelMessage`
- `core/channel/qq_channel_message.py`：`QQChannelMessage(ChannelMessage)`，`raw` 返回事件列表副本，`to_structured()` 每个 event 给一条 `event._data.model_dump_json()`
- `models/plugin_config.py`：`PluginConfig`（`enable: bool = True`、`buf_size: int = 30`，后者 `ge=0`）
- `config.example.yaml`：`enable` / `buf_size` 两项示例配置
- 子插件 `plugins/account_injector/`：`AccountInjector(PluginProtocol)`，`PluginConfig` 四个必填字段 `bot_id` / `admin_id` / `bot_nickname` / `admin_nickname`，`on_load` 把配置写进共享容器并 `registry.on(ON_AGENT_START, inject_account, priority=NORMAL)` 挂上节点
- 子插件 `plugins/account_injector/nodes/inject_account.py`：`inject_account(state, runtime)` 读 `PLUGIN_CONFIG` 拼出 `administrator id` / `administrator nickname` / `bot id` / `bot nickname` 四行，返回 `{"prompts": {"account-info": ...}}`
- 子插件 `plugins/qq_platform_tools/`：`QQPlatformTools(PluginProtocol)`，`on_load` 逐个 `register_tool()` 注册五个工具，`on_close` 回放注销函数
- 工具 `download_qq_file(url)`：走 `ncatbot_api.qq.file.download_file()`，下载结果 `model_dump_json()` 返回
- 工具 `send_message_to_qq(chat_id, mode, messages)`：逐段 `to_ob11()` 转换后交给 `miaoli_bot.utils.easier_send`，`mode` 取 `group` / `private`
- 工具 `delete_qq_message(message_id)`：走 `messaging.delete_msg()` 撤回
- 工具 `query_qq_message(message_id)`：走 `query.get_msg()` 查消息，结果 `model_dump_json()` 返回
- 工具 `send_poke(user_id, group_id=None)`：带 `group_id` 走 `messaging.send_poke()`，不带则走 `messaging.friend_poke()`
- 工具 `send_message_to_qq` 的 `ToolSchema` 校验器（`model_validator(mode="after")`）：`messages` 至少 1 条；`reply` 最多 1 条；`image` 最多 20 张，可与 `text` / `at` / `reply` 共存；`file` / `video` / `record` 合计最多 1 条；`text` / `at` / `reply` / `image` 与 `file` / `video` / `record` 不可混发 —— 越界一律 `raise ValueError` 并带上实际条数
- `plugins/qq_platform_tools/models/messages/`：`BaseMessage(BaseModel, ABC)` 带抽象 `to_ob11()`，`MediaMessage` 收拢 `file` / `url` / `path` / `name` / `thumb` 五个字段，七个消息段 `text` / `at` / `reply` / `image` / `record` / `video` / `file` 各自实现 `to_ob11()`，`Messages` 用 `Field(discriminator="type")` 组成判别联合
- 五个工具都把异常包成 `[操作失败: 异常类型: 内容]` 形式的字符串返回（`[撤回失败: ...]` / `[戳 <user_id> 失败: ...]` 等），不向上抛 —— 模型侧看到的是工具结果而不是节点异常

## Note

- `to_structured()` 返回的是 JSON 字符串，`miaoli_bot` 之后还会 `json.dumps` 一次，模型看到的是转义过的双层结构（`{"qq": ["{\"self_id\": ...}"]}`）
- 缓冲不过滤事件：灰条（`grayTipElement`）在 NapCat 侧不在可转消息段里，会变成 `message: []` 的空段事件但 `post_type` 仍是 `message`，这类事件同样会被记进缓冲
- `PluginConfig.enable` 有字段，但 `on_load` 与 `record_anything` 都没读它，改成 `false` 依然照样记录；要真关掉只能把插件从 `plugin_whitelist` 里摘掉
- `deque(maxlen=size)` 溢出时最旧的直接消失，既没有日志也没有计数
- 两个子插件都不自带加载器，由 `miaoli_bot` 的 `Loader` 装载，因此 `config.yaml` 的 `sub_plugin.load_from` 要同时包含 `plugins/miaoli_bot/plugins` 与 `plugins/miaoli_qq_channel/plugins` 两个目录；相对路径按 ncatbot 进程的工作目录解析
