# v0.10.0 - 2026-11-17

> 🧹 **回复先剥 markdown，再按空行逐条发**。`reply` 拿到正文后先用 `markdown` + BeautifulSoup 取纯文本（换行结构保留），文字路去掉每条末尾的句号，语音路从「整条合成一段」改成「按空行逐条各合成一段」。分条依据固定成空行，`split.delimiter` 配置项删除。

## Added

- `core/markdown/strip_markdown.py`：`strip_markdown(text)`。`markdown` 渲染（开 `nl2br`）→ BeautifulSoup 取纯文本：块级元素收尾补空行、行级元素收尾补单换行，因此**单换行仍是单换行、空行仍是空行**；图片留 `alt`、代码块留正文；以 `<` 开头的颜文字在渲染前先转义成 `&lt;`，不会被当成 HTML 标签连内容一起吞掉。
- `core/markdown/__init__.py`、`core/__init__.py`：转出 `strip_markdown`。
- `core/channel/qq_channel.py`：新增 `send_voice()` 与 `send_text()`，把「合成一条语音」和「发一条文字」各拆成一个方法；`reply` 只负责剥标记、切条、掷骰子和分流。

## Changed

- `core/channel/qq_channel.py` 的 `reply()`：正文在语音分支**之前**过一遍 `strip_markdown`，语音读的是剥过标记的正文，长度门槛数的也是剥过之后的字数。
- `core/channel/qq_channel.py` 的 `reply()`：分条改成按空行（`\n\n`）切，`split.enable: false` 时才整条发一条。
- `core/channel/qq_channel.py` 的 `reply()`：文字路每一条以 `。` 结尾时去掉一个句号再发（`endswith("。")`）；语音路不动。
- `core/channel/qq_channel.py` 的语音分支：骰子与长度门槛仍按**整条回复**判一次，判过之后把正文按空行切开，每一条各自合成一段 `record` 逐条发出；某一条失败（合成拿不到音频或 NapCat 拒收）只把这一条换成文字补发，其余仍走语音。
- `models/config/split_config.py`：`SplitConfig` 只剩 `enable`，分隔符固定是空行。
- `config.example.yaml`：`split` 段删掉 `delimiter`；`voice` 段注释改成「命中后按空行逐条各合成一段」。
- `manifest.toml`：`pip_dependencies` 从空改成 `markdown = ">=3.5"`、`beautifulsoup4 = ">=4.12"`。

## Removed

- `models/config/split_config.py` 的 `delimiter` 字段与配套的 `ensure_delimiter` 校验 —— 分条依据不再可配。

## Note

- **配置兼容**：`PluginConfig` 不过滤额外字段，旧 `config.yaml` 里留着 `split.delimiter` 不会报错，只是不起作用；想关掉分条仍然可以用 `split.enable: false`。
- **markdown 剥得比较狠**：表格会塌成一行一行的纯文本、行内代码只留内容、链接只留文字。QQ 文字消息本来也不渲染 markdown，这些标记发出去只会显得脏，所以是有意为之。
- **语音变慢的代价**：原来是整条合成一段，现在三句话就是三次串行的 7~15 秒合成。说得越多越慢，命中语音的那条回复会明显晚于打字节奏。
- **单条长度不再受 `min_chars` 约束**：门槛只判整条回复，判过之后单条可能是「嗯。」这种两三个字，照样合成。
- `pip_dependencies` 里只写了两个必要依赖；`httpx` 仍未声明，只有开语音时才需要。

## Docs

- `README.md`：版本、依赖、数据流、目录树、配置示例、语音章节全部同步；新增「回复前处理（剥 markdown / 分条 / 去句号）」一节；已知短板里补合成延迟按条累加。
