# v0.3.0 - 2026-11-07

> 🧱 **补上第一批条件节点**。0.2.0 只有决定器框架、一个节点都没注册，提交器永远拿不到「可以提交」的结论；本版新增 `base_judges` 子插件，把「被 @」和「被叫昵称」两条硬规则接进去。
>
> 到这一步，「有人在叫机器人」的消息能进渠道了；「没人叫但值得接一句」仍然进不去 —— 那要靠返回 `AddScore` 的软规则，本版还没写。

## Added

- 子插件 `plugins/base_judges/`，依赖 `account_injector`（账号从它的 `PluginConfig` 取，不重复配一遍）。
  - `judges/at_me.py`：消息里有指向机器人 QQ 的 `At` 段就返回 `MustReply(reason="被@")`。用 `is_at(bot_id, all_except=True)`，**`@全体成员` 不算被 @**；两者同时出现时仍算被 @（`is_at` 命中具体 uid 会提前返回）。
  - `judges/name_mentioned.py`：纯文本里出现 `bot_nickname` 就返回 `MustReply(reason="被叫昵称")`。昵称为空串时直接返回 `None`，否则任何文本都会被判成命中。
  - 优先级：`at_me` 用 `HIGH`（100），`name_mentioned` 用 `MEDIUM`（10）。两者同时命中时 `reason` 记成「被@」。
- `metadata.toml` 里声明 `dependences` 指向 `account_injector`，拓扑序保证账号配置先于节点注册就位。

## Changed

- 通道 README 的子插件从两个变三个，目录结构与「已知短板」同步更新。原有那条「本版没有任何条件节点、提交器一条都不会提交」改成「只有硬闸门、没有软规则」——行为不再是一条都不提交，而是**只有被 @ 或被叫昵称时才提交**。

## Note

- `data` 是 `tuple`，元素现在只有 `MessageEvent`，将来会混进 notice 事件，所以两个节点都先 `isinstance(event, MessageEvent)` 再取字段。
- 节点不读 `config.yaml`，昵称与 QQ 号全部归 `account_injector`，`base_judges` 没有自己的配置项。
- 不 @、不叫昵称的消息不会消失：它们留在积压缓冲里，等下一次硬闸门命中时被 `drain_into` 一起带进渠道（`buf_size` 满了才会从最旧的一端挤掉）。
