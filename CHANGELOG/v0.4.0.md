# v0.4.0 - 2026-11-10

> 🧱 **通道协议跟上主包，回复第一次真的发得出去**。主包把通道协议收窄成「一轮取一批消息、每条按自己的 `thread_id` 跑图、跑完用 `reply(thread_id, text)` 发回去」，本版把 `miaoli_qq_channel` 对齐过去：`drain()` 交回 `List[QQChannelMessage]`、消息补上新抽象成员 `to_content()`、`reply()` 从空壳变成真发消息。
>
> 两处破坏性变更：`drain()` 的返回类型变了、`BaseChannelMessage` 多了 `to_content()`，所以 minor 从 0.3 升到 0.4。

## Added

- `QQChannelMessage.to_content()`：主包 0.43.0 把 `to_content()` 定成 `BaseChannelMessage` 的第四个抽象成员，本版补上。**本轮与 `to_text()` 完全等价**，直接返回它的结果；NapCat 图片要 base64、需要多模态解析的那部分没有做。
- `QQChannel.reply(thread_id, text)`：按 `thread_id` 前缀反解出发送模式与会话号，正文按 `split` 配置切成几条，逐条走 `easier_send` 发回 QQ。每段发之前按 `typing` 配置随机 sleep 一下模拟打字。
- 配置段 `split`（`models/config/split_config.py`，`SplitConfig`）：`enable` / `delimiter`。启用分割时分隔符为空会在校验期报错，不会切出空段。
- 配置段 `typing`（`models/config/typing_config.py`，`TypingConfig`）：`enable` / `base_speed` / `speed_offset`，每字耗时在 `base_speed ± speed_offset` 之间随机。
- `runtimes/judge_context.py` 的 `JudgeContext`（`@dataclass(frozen=True)`）：`time` / `data` / `submitted_time` / `submitted_data` 四个字段，条件节点不再直接收事件列表。新增共享容器键 `JUDGE_CONTEXT`（`miaoli_qq_channel/runtimes.judge_context`）保存上一次成功提交的那份上下文。
- `plugins/base_judges/judges/private_chat.py`：不是群消息就返回 `MustReply(reason="私聊")`，优先级 `NORMAL`，排在 `at_me` / `name_mentioned` 之后当兜底。

## Changed

- `QQChannelMessage` 的基类从 `ChannelMessage` 换成 `BaseChannelMessage`：自己算 `thread_id`（`group-<群号>` / `private-<QQ号>`，前缀取主包的 `GROUP_PREFIX` / `PRIVATE_PREFIX`）、`platform` 固定 `"qq"`、`to_text()` 把整套事件序列化成一份 JSON 字符串。
- `QQChannel.drain()` 的返回类型从单个 `QQChannelMessage` 变成 `List[QQChannelMessage]`：一次把缓冲取空，按 `thread_id` 分组，每个会话打包一条，组内 `旧 → 新`，组间按各自最旧的事件排序。
- `JudgeDecider.decide()` 的参数从事件序列换成 `JudgeContext`，内部不再 `tuple()` 冻结 —— 冻结改在 `JudgeContext` 自己身上（frozen dataclass）。
- 提交器 `auto_submit()` 每轮用当轮事件与上一次提交的上下文拼出 `JudgeContext` 再交给决定器；提交成功后 `store_set(JUDGE_CONTEXT, ...)` 记下来，不成功不更新。
- `base_judges` 的三个节点签名从 `(data: Sequence[Any])` 改成 `(ctx: JudgeContext)`，读事件改从 `ctx.data` 取。
- `on_close()` 除了注销节点，还要撤掉 `JUDGE_CONTEXT` 的 store 绑定。
- `manifest.toml` 与 README 的依赖声明从 `miaoli_bot >= 0.41.0` 改成 `>= 0.43.0`。

## Removed

- `QQChannelMessage.raw` 属性与 `to_structured()` 方法：主包 0.42.0 起通道协议只认 `thread_id` / `platform` / `to_content` / `to_text`，逐条 `model_dump_json()` 的接口没有人再调用。

## Fixed

- `config.example.yaml` 里的顶层 `buf_size` 换成 `channel.buf_size` / `message.buf_size`：旧样例的字段名与 `PluginConfig` 对不上，照它写配置会静默落进默认值。同时补上 `submit` / `judge` / `split` / `typing` 四段。

## Note

- `to_content()` 是与 `to_text()` 等价的临时实现：两者都返回同一份 JSON 字符串，主包跑图拿到的是 `HumanMessage(str)`。要真支持多模态（图片转 base64 丢给模型）得改 `to_content()` 并让它返回消息段列表，属于后续工作。
- `drain()` 一次交全会话，缓冲不留尾巴；代价是主包一轮 tick 里这批会话串行跑完才结束，会话多时单个 tick 会很长。
- `JudgeContext` 是 `frozen` 的，节点读得到、改不了；`submitted_data` / `submitted_time` 首次为 `None`。
- `typing` 的两个默认值都是 0，`enable` 开着也等于不等待；`config.example.yaml` 给的是 `0.06 ± 0.02`。

## Docs

- `plugins/base_judges/README.md` 补上第三个节点 `private_chat` 的规则与优先级，数据形态一节从「`data` 是 `tuple`」改写成「节点收到 `JudgeContext`」。
