# v0.16.0 - 2026-11-25

> 🛤️ **跟随拆成独立通道**：被叫回复完成后，该会话进入跟随；跟随里的消息不再受缓冲区默认策略（`quiet` 静默 / `chance` 随机）影响，**下个 tick 直接提交**，并改用 `follow.*` 自己的时长与限流配置。

## Breaking

- 删除 `social.follow_up` / `social.follow_quiet` / `social.follow_min_unread` / `social.speak_cooldown_seconds` / `social.active_min_minutes` / `social.active_max_minutes`，由新的顶层 `follow` 段取代。旧字段会被 pydantic 忽略。
- `WakeReason.ACTIVE` 更名 `WakeReason.FOLLOW`，快照理由文案「聊天状态跟一句」→「跟随中接话」。

## Added

- 顶层 `follow` 配置（`models/config/follow_config.py`）：
  - `enable`（默认 `false`）：跟随开关；
  - `duration_minutes`（默认 `10`）：一次跟随最长持续，每次成功提交后重新计时；
  - `min_interval_seconds`（默认 `3`）：跟随中两次提交的最小间隔；
  - `max_submit_per_minute` / `max_submit_per_hour`（默认 `2` / `30`）：跟随自己的限流，与 `social.*` 互不影响。
- `SessionSocial.follow_until`：跟随时间窗；由「回复完成」或「跟随中的一次提交」开启，被叫进入 active 本身不算。
- `SocialStore.is_following()`：统一判断跟随，供 `decide()` / `can_submit()` / `Scheduler` 使用。

## Changed

- `SocialStore.decide()`：active 且跟随中 → 直接返回 `FOLLOW`，不再检查静默/冷却/未读数。
- `Scheduler.submit_if_due()`：跟随中的会话跳过 `social.quiet` 静默检查；被叫窗口仍按 `quiet` 攒批后才提交。
- `SocialStore.on_submit()` 增加 `config` 参数（跟随续期 + 状态刷新）。
- 测试 57 个：新增「跟随下个 tick 提交」「跟随最小间隔」「跟随时长到期回潜水」「跟随自己限流」用例。
- README、`config.example.yaml`、`docs/social-state-machine.md`（§5 状态与不变式、§11 配置、§16.2）同步。

## Notes

- 跟随期间一轮跑图要 1~3 分钟，在途期间消息继续攒；回复完成后下个 tick 才会再提交，所以实际节奏 ≈ 每次回复耗时。
- 提醒/主动话题等仍在设计稿里的能力保持未实现。
