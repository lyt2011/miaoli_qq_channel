# v0.8.0 - 2026-11-15

> 🔊 **回复可以出声了**。`voice` 段打开后，每条回复掷一次骰子，命中就把**整条回复**交给 `edge-tts` 合成一条 mp3，用 `record` 段发出去。默认关，不开不影响原有行为。

## Added

- `models/config/voice_config.py`：`VoiceConfig`（`enable` / `probability` / `voice` / `pitch` / `rate` / `min_chars` / `max_chars`），`enable` 默认 `false`，`voice` 默认 `zh-CN-XiaoyiNeural`。
- `core/tts/synthesize.py`：`synthesize(text, voice, pitch, rate) -> Optional[bytes]`，用 `edge_tts.Communicate(...).stream()` 收 `type == "audio"` 的块拼成 mp3 字节，**全程内存不落盘**；异常或空音频返回 `None` 并留一条 warning。
- `config.example.yaml`：新增 `voice` 段。

## Changed

- `core/channel/qq_channel.py` 的 `reply()`：判定时机挪到切分**之前**，一次回复只跑一次 `random()` —— 命中就整条合成、整条用一条 `record` 发出并 `return`，不命中或失败才走原来的按段文字。
  - 长度门槛量的是**说出来的字数**（`"".join(whole.split())`，换行与空白不计），合成时仍送原文本，换行造成的停顿保留。
  - 语音那条不补打字延迟 —— 合成本身已经花掉时间。
- `core/__init__.py`、`models/config/__init__.py`：转出 `synthesize` / `VoiceConfig`。
- `models/plugin_config.py`：`PluginConfig` 多一个 `voice` 段。
- `models/config/corpus.py`：`from typing` 那行的缩进对齐到 tab stop 4，纯空白改动。

## Note

- 回退路径明确：合成抛异常、返回空音频、`record` 段被 NapCat 拒收，三种都只 `warning` 一笔然后退回按段文字，消息不会丢。
- 粒度是整条回复，不是一段。两段话的组合算一条语音，`split.delimiter` 在语音分支里不参与。
- `edge-tts` 是可选依赖，只有 `voice.enable: true` 才需要装。
- 只能调 `rate` / `pitch` / `volume`；Azure 的 `style`（cheerful / sad / angry 之类）edge-tts 不暴露。
- `base64://` 还没在真机验证：合成、拼段、回退逻辑都有测试，但 NapCat 收不收一段 20~40 KB 的 `base64://` 待实测。回退到 `file://` 要写盘加清理，没做。

## Docs
